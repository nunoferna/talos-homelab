# Keycloak

The official namespace-scoped operator uses upstream release tag `26.8.1`
(verified commit `81948d26747a61e5348f0f3c832d017b36a9cb1c`). Release commits
exist only on tags, so Flux must fetch the tag rather than use its commit-only
strategy. Operator/server images remain digest-pinned.
No OLM or experimental Helm chart. Bootstrap admin credentials are generated by
the operator; database credentials are generated by CNPG. Neither depends on
OpenBao/ESO, avoiding a circular dependency for human OIDC login.

One existing CNPG 1.30.1 controller watches exactly `openbao,keycloak`, with
separate namespace Roles. Its watch-list update rolls only that operator, not
OpenBao or its database. Keycloak uses its own PostgreSQL 17.11 instance, 4Gi
Retain PV, credentials and `/var/mnt/keycloak-poc` directory. This is disposable
single-node storage on the existing filesystem: no HA, disk quota or backup.
The existing accepted CNPG/Kubernetes 1.37 PoC exception still applies.

Merge private site inputs first. Initial reconciliation installs the operator
and namespace prerequisites; `keycloak-database` and `keycloak` remain suspended.
Review a fresh encrypted Talos plan, then deliver only the new host mount through
reviewed local Ansible before activating the database and server in Git.
Do not replay the old OpenBao mount plan or delivery workflow.

The prepared HTTPRoute uses the existing gateway HTTPS listener. The internal
HTTP backend accepts only Cilium's ingress identity; management stays internal.
PostgreSQL requires TLS with server verification. The bounded `unsupported`
pod-template override projects only `ca.crt` from CNPG's CA Secret and sets
restricted pod security; it must be checked when upgrading the operator.

After activation: verify database/Keycloak readiness, route conditions, HTTPS
and OIDC discovery from Mac and OpenBao. Establish a permanent administrator with
MFA and remove the temporary bootstrap account before configuring application
clients. Human enrollment and OpenBao OIDC remain a later step; ESO keeps using
Kubernetes authentication. Removing Flux objects does not delete persistence.
