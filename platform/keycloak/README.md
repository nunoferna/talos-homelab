# Keycloak

The official namespace-scoped operator uses upstream release tag `26.8.1` and
digest-pinned operator/server images. Bootstrap admin credentials are generated by
the operator; database credentials are generated by CNPG. Neither depends on
OpenBao/ESO, avoiding a circular dependency for human OIDC login.

One existing CNPG 1.30.1 controller watches exactly `openbao,keycloak`, with
separate namespace Roles. Its watch-list update rolls only that operator, not
OpenBao or its database. Keycloak uses its own PostgreSQL 17.11 instance, 4Gi
Retain PV, credentials and `/var/mnt/keycloak-poc` directory. This is disposable
single-node storage on the existing filesystem: no HA, disk quota or backup.
The existing accepted CNPG/Kubernetes 1.37 PoC exception still applies.

The reviewed host mount and separate PostgreSQL instance are Ready. `keycloak`
now reconciles the server and HTTPS route. Do not replay completed mount plans
or delivery workflows.

The prepared HTTPRoute uses the existing gateway HTTPS listener. The internal
HTTP backend accepts only Cilium's ingress identity; management stays internal.
PostgreSQL requires TLS with server verification. The bounded `unsupported`
pod-template override projects only `ca.crt` from CNPG's CA Secret and sets
restricted pod security; it must be checked when upgrading the operator.

The permanent master administrator uses verified passkey-only browser login;
the temporary user and master password grants have been retired. Application
identities belong to the separate `homelab` realm. Reviewed private automation
uses a public CLI client with browser login and PKCE, preserving that boundary.
OpenBao OIDC uses a separate confidential client and a group-bound role; ESO
continues to use Kubernetes authentication. Removing Flux objects does not
delete persistence.
